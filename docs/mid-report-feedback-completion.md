# 중간보고서 피드백 반영 완료

0929 회의 7번의 후속 정책: 문서 재제출은 필수가 아니며, 담당 교수자가 반영 여부를 판단해 완료 처리한다. 교수님 피드백에 따라 후속 정책을 조정한다.

## API

`PATCH /api/v1/admin/sections/{sectionId}/teams/{teamId}/mid-report/feedback/complete`

```json
{"version": 3}
```

- 해당 활성 분반의 담당 교수자만 호출할 수 있다. 팀도 해당 분반 소속이어야 한다.
- 기존 보고서 상세 조회 응답의 `version`을 전달한다. 최신 버전과 다르면 409를 반환하므로 다시 조회해 판단해야 한다.
- 피드백 수정 요청이 존재하는 보고서만 완료할 수 있다. 학생이 이미 재제출한 경우도 교수자가 완료 확인할 수 있다.
- 문서 재제출이나 블록 완료 여부를 추가로 요구하지 않는다. 교수자는 현재 저장된 문서를 확인하고 완료한다.
- 완료 후 보고서 상태는 `SUBMITTED`가 되어 학생 수정이 잠긴다. 새 피드백 등록 시 기존 수정 요청 흐름으로 다시 열린다.
- `submittedAt`, `submittedBy`, `revision.resubmittedAt`은 학생 제출 정보이며 완료 처리로 변경하지 않는다.
- 어드민과 학생의 상세 응답 모두 `revision.completedAt`, `revision.completedBy`를 추가로 반환한다. 재제출 여부와 교수자 확인 여부는 별개다.
- 현재 버전으로 이미 완료된 요청을 반복하면 기존 완료 정보를 반환하고 새 기록은 적재하지 않는다.
- 완료 처리자와 일시는 기존 MID_REPORT 팀 메시지 이력에도 남긴다. 새 피드백이 현재 revision을 초기화해도 이전 완료 기록은 이력에 유지된다.

## 배포 및 연동

- 완료 정보는 기존 `revision_data` JSON에 저장하므로 신규 테이블/컬럼이나 별도 SQL 적용은 필요하지 않다.
- 기존 JSON에 완료 필드가 없으면 미완료(null)로 읽는다.
- API/Admin을 같은 버전으로 배포한다. 이전 서버가 문서를 저장하면 새 JSON 필드를 유지하지 못할 수 있다.
- 프론트의 완료 버튼은 현재 보고서 버전을 전달하고 응답으로 상세 상태를 갱신한다. 409는 자동 재시도하지 말고 최신 문서를 확인하게 한다.
- 피드백 이력에는 완료 안내 메시지도 포함된다. 현재 단계 완료 표시는 메시지 문자열이 아닌 `revision.completedAt` 기준으로 한다.
- DB·운영 환경 변경과 실제 화면 QA는 이 구현에 포함하지 않는다.
